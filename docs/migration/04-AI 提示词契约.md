# 04 · AI 提示词契约（深读层怎么交给别的模型跑）

> 深读层是**唯一需要 LLM 的部分**，也是迁移时最需要小心的部分。
> 本文说明：它要什么输入、必须产出什么、质量如何判定、换模型要注意什么。

---

## 1. 输入 / 输出：只有一个契约

```
输入（全部是文件，没有函数调用）
  scripts/daily-agent.md            提示词本身（含 schema 与纪律）
  web/data/deep-read-plan.json      工作清单：queue + backfill
  web/data/items/index.json         条目原文（标题 / 摘要 / url / categoryHits）
  web/data/digest/today.json        本轮新增
  web/data/manifest.json            本轮状态与失败渠道
  web/data/formulas.json            已有公式 id（避免重复造）
  config/collector.config.json      关注方向与权重

输出（只写这四个文件，且必须"读旧合并"）
  web/data/enrichment.json          深读结果（按 item id 键控）
  web/data/formulas.json            新公式（按 id 去重后追加）
  web/data/jobs.json                新岗位（追加，不改 relevance 公式）
  web/data/proposals/YYYY-MM-DD.json 提案（+ 同步 latest.json）
  web/data/logs/agent-YYYY-MM-DD.json 运行记录
```

**Agent 绝对不碰前端代码、不改 `items/index.json`。**
这条边界让"Agent 挂了"和"数据坏了"完全解耦。

---

## 2. 六个铁律（违反即任务失败）

1. **禁止编造。** 每条结论必须能在 `items/index.json` 的标题/摘要里找到依据。不确定写「待核实」。
2. **禁止编造 URL。** 只能用数据里已有的 `url` / `sources[].url`。
3. **不抓需要登录的站点**（小红书 / BOSS直聘 / 拉勾 / 实习僧）。需要就在提案里写"需人工导入"。
4. **不改前端代码。** 只写上面列出的 `web/data/` 文件。
5. **不减小已有数据。** 写 JSON 前先读旧文件，**合并**而非覆盖。
6. **UTF-8 无 BOM。** 用 Python `json.dump(..., ensure_ascii=False)`；不要用 PowerShell 的
   `Set-Content` / `>`（会写 BOM 并损坏中文）。

> 第 5 条是最容易出事的：直接覆盖 `enrichment.json` 会**不可逆地丢掉历史解析**。

## 3. 每条深读必须产出什么

### 3.1 五件套（缺一即未完成）

| 字段 | 说明 |
|---|---|
| `tldr` | 一句话结论，≤60 字 |
| `keyPoints[]` | 3–5 条要点，**必须来自原文摘要** |
| `diagram` | **图解，硬性要求**（见 3.2） |
| `teaching` | **讲解层，用多种方式教**（见 3.3） |
| `concepts[]` | 概念易读化：大白话 + 类比 + 类比失效点 + 机制 + 自测题 |
| `selfCheck` | `claims[]`（能证实的）+ `uncertain[]`（待人工核实） |

### 3.2 `diagram`：图解（硬性要求）

```jsonc
"diagram": {
  "kind": "flow | architecture | curve | matrix | timeline",
  "title": "≤20 字", "caption": "一句话说明想让人记住什么",
  "svg": "<svg viewBox='0 0 480 200' xmlns='http://www.w3.org/2000/svg'>…</svg>",
  //   或
  "spec": {"type": "flow", "nodes": [{"label":"","detail":""}],
           "edges": [{"from":0,"to":1,"label":""}]},
  "alt": "读屏替代文字（必填）"
}
```

**画图纪律**：
- **自包含**：无 `<image>`、无外链 `<use>`、无外部 `url()`
- 宽高比 16:6 ~ 16:9，`viewBox` 留 12px 边距，字号 ≥ 13（手机上要看得到）
- 颜色**只用**：`currentColor` / `var(--accent)` / `var(--fg-1)` / `var(--line-1)`
  —— 六套主题都要能正常显示
- 画不出来**不要编**：宁可用 `spec` 画一个朴素流程

### 3.3 `teaching`：用**至少 3 种**方式讲同一件事

这是"讲解 / 教学 / 官方口径 / 自己的思考"四者结合落到字段上的形式。
必须包含 `mechanism`、`boundary`、`analogyBoundary`（它们是"真懂"的证据）。

```jsonc
"teaching": {
  "progressive": [                       // ① 由浅入深
    {"level": "一句话", "text": "≤40 字，外行也能听懂"},
    {"level": "入门",   "text": "≤120 字"},
    {"level": "进阶",   "text": "≤200 字，说清关键设计选择与取舍"},
    {"level": "专家",   "text": "≤260 字，与其它方法对比、适用边界"}
  ],
  "socratic": [{"q": "如果不做这一步会怎样？", "a": "≤100 字"}],   // ② 追问式
  "mechanism": "≤200 字，说清『为什么必须这样设计』",             // ③ 必填
  "boundary": "≤160 字，什么时候不适用 / 会失效",               // ④ 必填
  "analogyBoundary": "≤140 字，类比的失效点",                   // ⑤ 必填
  "misconceptions": ["≤80 字/条，2-3 条"],                      // ⑥ 常见误解
  "ownAnalysis": "≤220 字；推断必须显式标注『（推断）』",         // ⑦ 自己的思考
  "officialNotes": [{"position": "官方口径", "source": "只能来自数据里的 url/来源名"}],  // ⑧
  "interviewAnswer": "≤200 字，第一人称像在面试现场说出来",       // ⑨ 面试怎么答
  "studyPath": {"prerequisites": ["…"], "nextSteps": ["…"]}     // ⑩ 学习路径
}
```

**`ownAnalysis` 的纪律**：允许推理，但凡是推断必须写「（推断）」或「（待核实）」，
不要冒充原文结论。这是这套系统"不骗人"的底线。

### 3.4 `formulas[]`：五层齐全

符号表 → 推导链条 → 生活类比 → 可运行代码 → 易错点。缺层视为未完成。

> ⚠️ `latex` 必须能被工作台**自研的 `tex()` 渲染器**解析（不是完整 TeX）。
> 一条解析失败的公式会让「公式剖析」**整页空白**，因此有门禁
> `node scripts/check-formulas.mjs`（失败则拒绝发布）。

## 4. `deep-read-plan.json`：Agent 的工作清单

**不许自己另挑条目。** 清单由确定性层生成，好处是可复核：
你可以质疑它、人工改它，下一轮还能对比「计划 vs 实际」来评估筛选规则好不好。

| 键 | 含义 | Agent 要做什么 |
|---|---|---|
| `queue` | **尚未深读**的条目 | 从零产出完整五件套 |
| `backfill` | **已深读但解析不完整** | 按 `missing` 字段**只补缺的那几层**，不重写已有内容 |
| `skimmed` / `skimByRule` | 被质量闸门挡掉的 | **不要**深读（它们仍在库里可搜索） |

`backfill[].missing` 可能包含 `diagram` / `formulas` / `teaching` / `concepts`。
`backfillWeight` 越高越优先（缺图解权重最高，因为它是**可见**的缺陷）。

## 5. 质量如何判定（迁移时照搬这些检查）

| 检查 | 命令 / 方式 | 期望 |
|---|---|---|
| JSON 全部可解析 | `python -c "import json,glob;..."` | 无异常 |
| 每条都有图解 | 检查 `diagram.svg` 或 `diagram.spec` | 100% |
| 公式五层齐全 | 检查 `symbols/derivation/analogy/code/pitfalls` | 无缺层 |
| LaTeX 能渲染 | `node scripts/check-formulas.mjs` | 0 失败 |
| 不减小已有数据 | 对比前后 `count` 与 `byId` 键数 | 只增不减 |
| 自检通过 | `python scripts/selfcheck.py` | 0 错误 |
| 契约一致 | `python scripts/verify_web_data.py` | 无新增 FAIL |

## 6. 换模型 / 换平台时的注意事项

### 6.1 它与平台解耦在哪
提示词只要求两件事：**能读写文件**、**能跑 Python**。
没有对任何 CLI 名、工具名、模型名的依赖。所以 Claude Code / Cursor / Codex /
自建 API 调用 / 任何 agent 框架都能执行。

### 6.2 换模型后最容易退化的三点（实测观察）
1. **图解质量**：小模型倾向画极简方框，或干脆用文字冒充图。
   → 迁移后务必跑一次「每条都有图解？图里有没有外部引用？」的检查。
2. **纪律遵守**：模型越弱越容易"帮你想" —— 编 URL、把推断写成结论、
   整体覆盖而不是合并。→ 铁律要在提示词里**放在最前面**（现在的结构就是这样）。
3. **产出规模**：任务量大时模型可能改去做"基础设施"（真实发生过：一次运行里
   Agent 花了全部时间写 24 批次的批处理脚本，没产出任何深读内容）。
   → **单轮工作量要收敛**：用 `scope_deep_read.py` 把队列缩到可完成规模，
   或明确要求"先产出 N 条再考虑工具化"。

### 6.3 建议的调用形态（任何平台）

```
工作目录 = 仓库根
提示词   = scripts/daily-agent.md 的全文（含 {{DATE}} {{ROOT}} 替换）
超时     = 至少 20 分钟（实测 13 条深读约 450 秒）
失败处理 = 非致命：记录日志，不阻断采集与发布
```

`{{DATE}}` / `{{ROOT}}` 是最初的两个占位符，`run-daily.ps1` 会替换后从 stdin 传入。

### 6.4 增量与幂等
- `enrichment.json` 按 id 键控 → 同一条重复深读是**覆盖**，不会重复
- `formulas.json` 按 id 去重后追加
- `jobs.json` 追加时按 `id` 判重
- 因此**重跑是安全的**，可以放心分批次做

## 7. 一个可以直接复制的提示词外壳（非 Windows）

```text
你正在为「Future · 求职学习工作台」执行每日深读。工作目录：<repo 根>
请完整阅读并严格遵守：scripts/daily-agent.md

要点复述（若与其冲突，以那个文件为准）：
1. 工作清单是 web/data/deep-read-plan.json 的 `queue` 与 `backfill`，不要自己挑条目
2. 每一条都必须产出 diagram（内联 SVG 或 spec）与 teaching（≥3 种讲解方式）
3. 禁止编造结论与 URL；不确定写「待核实」；推断要标注「（推断）」
4. 只写 web/data/ 下指定的文件，且必须读旧合并，不许整体覆盖
5. UTF-8 无 BOM，用 Python 写 JSON
6. 最后输出 ≤200 字中文汇报 + 需要人确认的事项
```

## 8. 提示词放在哪、怎么改

| 文件 | 作用 |
|---|---|
| `scripts/daily-agent.md` | **唯一的提示词源**。改这里就改了行为 |
| `scripts/run-daily.ps1` | 读取它、替换 `{{DATE}}`/`{{ROOT}}`、通过 stdin 传给 CLI |

修改提示词后**建议**做一次小样本验证（`scope_deep_read.py` 缩到 3–5 条），
确认新要求被采纳，再放回每日流程 —— 提示词改动是最容易"看起来对但模型没照做"的地方。
