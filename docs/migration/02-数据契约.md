# 02 · 数据契约（Data Contract）

> 迁移到任何平台时，**这份契约是唯一不能改的东西**。
> 接口 = `web/data/` 下的 JSON 文件；没有数据库、没有 HTTP API、没有 ORM。
> 下面每个结构都来自当前文件的实测。

---

## 0. 总原则

| 原则 | 说明 |
|---|---|
| **文件即接口** | 前端只通过 `fetch('data/*.json')` 读数据；没有服务端 |
| **`items/index.json` 是唯一真相** | 其它文件是它的视图、派生或侧车（sidecar） |
| **侧车与语料解耦** | `enrichment.json` / `formulas.json` 按 id 键控，重建语料不丢解析 |
| **id 必须稳定** | `sha1(sourceId + externalId)[:16]`，换平台**不要改算法** |
| **时间带偏移** | ISO-8601 + `+08:00`；内部算 UTC，展示 Asia/Shanghai |
| **原子写** | 一律 `写临时文件 → os.replace`，避免半截文件 |
| **UTF-8 无 BOM** | 中文 JSON 全部由 Python 写（`ensure_ascii=False`） |

### 稳定 id 算法（契约的一部分）
```python
def stable_id(source_id: str, external_id: str) -> str:
    return hashlib.sha1(f"{source_id}|{external_id}".encode("utf-8")).hexdigest()[:16]
```
**改了会怎样**：所有历史 `enrichment` / `formulas` / 收藏 / 学习进度**全部对不上**，
去重记忆清零。迁移时若必须改，要写一次性迁移脚本重映射 id。

## 1. `items/index.json` — 知识卡片全量（唯一真相）

```jsonc
      "summarySource": "page-meta-description",  // 可选：说明摘要来源，可审计

      },
      "categoryHits": ["inference", "serving"],   // 命中的关键词（空数组 = 未分类）

```

**派生字段（前端合并侧车后才存在，不在这个文件里）**：
`enriched` / `tldr` / `keyPoints` / `why` / `difficulty` / `concepts` / `selfCheck` /
`diagram` / `teaching` / `hasAnalysis` / `hasDiagram`。

> 前端在 `Store.boot()` 里把 `enrichment.byId[id]` 合并到对应 item 上再渲染。
> 这样「重建语料不丢解析、Agent 失败不污染语料」。

**`category` 的两个特殊值**：
- `unclassified` —— 没有任何关键词命中（会被扣 12 分，排在最后）
- 未知值 —— 前端 `mapCategoryAlias()` 会兜底映射，但**不要依赖兜底**，应写合法 id

### 1.1 知识质量字段（`kind` / `materiality` / `directionFit` / `qualityFlags`）

由 `scripts/knowledge_quality.py` 计算并写进每个 item。**这是全工作台唯一的
"这条内容值不值得留 / 值得深读"判断**，采集器、深读规划器、卡片清理器、自检
四处共用同一份结论，不允许任何一处自行另立规则。

| 字段 | 取值 | 含义 |
|---|---|---|
| `kind` | `paper` / `repo` / `interview` / `problem` / `notes` / `course` / `job` / `news` / `other` | 知识类型。论文 / 仓库 / 面经 / 手撕笔试题 / 知识点八股 / 课程 / 岗位 / 资讯 / 其它 |
| `materiality` | 0–1（float） | **知识材料性**：实质内容 + 可核验证据（代码/评审/CCF/star）+ 可复用材料（公式/推导/实现）+ 类型耐久性。**刻意不含"新鲜度"** |
| `directionFit` | 0–1（float） | 与「多模态 / 后训练 / 生成式 / 世界模型 + 算法岗」的贴合度。0 = 与目标方向无关（Java 后端面经、秋招情绪帖） |
| `qualityFlags` | string[]（可选） | 命中的硬噪音规则 id：`career-vent` / `generic-question` / `referral-code` / `salary-thread` / `off-topic-hot` / `promo` |
| `knowledgeBase` | `true`（可选） | 来自白名单知识库渠道（代码随想录 / 卡码笔记 / 小林coding / CodeTop / 题解仓库）。这些卡片的摘要是**指针**而非正文，且 family 白名单本身就是方向过滤器，因此豁免"材料性门槛"与"分类饱和上限" |

**打分里的两个新分量**（见 `relevanceBreakdown`）：`materiality`（= 权重 ×
(materiality − 0.5)，中性点 0.5）与 `ephemeral`（`kind == news` 时的固定扣分）。
幅度由 `config/collector.config.json` 的 `knowledge` 段控制，**改口径不用改代码**。

### 1.2 技术材料的「方向门槛」（论文 / 仓库 / 课程）

`directionFit` 含宽口径兜底词（ai / cv / nlp / 算法…），几乎任何 ML 内容都能命中，
所以它只能回答"这是不是求职相关的技术内容"。判断一篇论文**是否落在目标方向上**
用的是更严的 `core_fit()`（只数 `CORE_DIRECTION_TERMS` 里的具体技术词），并由
`technical_reject()` 给出统一的取舍结论：

| 判据 | 结论 |
|---|---|
| arXiv 学科标签全在 CS/ML 之外（`cond-mat.*` / `math.*` / `astro-ph.*` / `physics.*` …） | 拒收：非计算机学科论文 |
| 命中窄领域（医学/遥感/物理化学/工业/金融社科）且 `core_fit < 1.0` | 拒收：单一领域应用，方法不可迁移 |
| `core_fit < minCoreFitForTechnical`（默认 0.5，即一个具体技术词都没有） | 拒收：只靠泛化的 AI 词命中 |
| `materiality < minKeepMateriality` | 拒收：没有实质内容 |
| 其余 | 保留；`core_fit ≥ 1.0` 且有代码/评审时判 `core`，否则判 `useful` |

> **两处调用同一个函数**：`collect.py` 的入库闸门与 `importance()` 的分档都调
> `technical_reject()`，所以不可能出现"采集放进来、清理又要删掉"的自相矛盾。
>
> 实测依据（2026-10-03 全库）：`marital health`（婚姻健康研究）、`quantum fluids
> of light`、`mouse grimace scale`、`Photospheric Vector Field`（太阳物理）等论文，
> 此前靠 `arxiv` 标签 / `diffusion` / `attention` 这类词混进库里。修复前 401 篇
> 论文里 38 篇属于此类。
>
> 配套修掉的另一个缺陷：`_term_re()` 此前用 `(?![0-9a-z])` 做词边界，**复数一律
> 匹配不上**（`llm` 匹配不到 `LLMs`、`scaling law` 匹配不到 `scaling laws`），
> 导致真在方向内的论文被判为不相关。

### 1.3 论文的分类饱和上限（清理"冗余"）

实测文献库**没有任何字面重复**（近似标题 Jaccard ≥ 0.45 的对为 0），但数量饱和：
后训练 89 篇、Agent 72 篇。对备考来说第 60 篇"又一个 GRPO 变体"边际价值接近零，
却会把关键的少数几篇淹掉。所以 `library_over_cap()` 给**论文**设分类上限：

- 目标方向（multimodal / posttraining / generative / worldmodel）：`maxPapersPerCategoryTarget`（当前 34）
- 邻近方向（agent / rl / engineering / foundation …）：`maxPapersPerCategory`（当前 26）
- 排序用 `paper_value_key()`：**技术贴合 → 材料性 → 有无开源实现 → 同行评审/CCF
  → 相关度（仅同档打平）**。刻意不以新鲜度优先。
- 只作用于 `kind == paper`，且豁免 `knowledgeBase`；面经 / 手撕题 / 八股 / 岗位
  不受限（那些是求职资产，越多越好）。

在下架时，两类删除的理由都会被完整写进归档文件（`data/archive/pruned-<date>.json`）
与 `proposals` 的 `humanReviewQueue`，可逐条复核。

> ⚠️ 这些字段是**判断**，不是**决定**：真正的下架仍只由 `prune_items.py --apply`
> 执行，并且会写 blocklist（否则下一轮采集立刻复活）。饱和上限删除的论文也写
> blocklist —— 代价是被封的条目不会因为库变小而自动回来，收益是库不会每天
> 「收进来又踢出去」地抖动。要放回某一条：从 `state/collector-state.json` 的
> `blockedIds` / `blockedTitleKeys` 中删掉它，再跑 `collect.py --rescore`。

```jsonc
      "teaching": {
        "progressive": [{"level": "一句话", "text": "..."},

      // ③ 概念易读化
      "concepts": [{
        "name": "...", "readable": "大白话 ≤100 字",
```

## 6. `formulas.json` — 公式剖析（五层齐全）

```jsonc
{
  "generatedAt": "...", "source": "seed+daily", "count": 54,
  "formulas": [{
    "id": "f-attention",                       // 稳定 slug
    "name": "缩放点积注意力 (Scaled Dot-Product Attention)",
    "category": "multimodal|posttraining|worldmodel|generative|rl|agent|foundation|engineering",
    "glyph": "A", "tags": ["attention"],
    "latex": "\\mathrm{Attention}(Q,K,V)=...",  // 前端自研 tex() 渲染；必须能被它解析
    "symbols": [["Q ∈ R^{n×d_k}", "查询矩阵"]],  // 注意：数组的数组，不是对象
    "derivation": ["逐步推导，2-5 步"],
    "analogy": "生活类比",
    "code": "可运行的 PyTorch 片段",
    "pitfalls": ["面试易错点"],
    "sources": [{"title": "...", "url": "必须来自数据里已有的 url"}]
  }]
}
```

**五层必须齐全**：符号表 → 推导链条 → 生活类比 → 可运行代码 → 易错点。
缺层视为未完成（`audit_requirements.py` 会检查）。

> ⚠️ **LaTeX 必须能被自研渲染器解析**。它**不是**完整 TeX 实现。
> 一条解析失败的公式会让「公式剖析」**整页空白**（页面是一个大模板字符串）。
> 因此每日流程里有**门禁** `node scripts/check-formulas.mjs`，失败则拒绝发布。

## 16. `interview.json` — 面经结构化抽取（可选，每日生成）

```jsonc
{
  "generatedAt": "...", "source": "build_interview_index.py (deterministic rules, no LLM)",
  "count": 26,
  "companies": [{"name": "字节跳动", "count": 5}],
  "rounds":    [{"name": "一面", "count": 14}],
  "topics":    [{"name": "项目/论文深挖", "count": 15}],
  "outcomes":  [{"name": "通过", "count": 18}],
  "withCoding": 5,
  "items": [{
    "id": "...", "title": "...", "url": "...", "channel": "nowcoder",
    "publishedAt": "2026-10-01T...", "company": "字节跳动", "round": "二面",
    "outcome": "未通过", "topics": ["工程/系统"], "hasCoding": true
  }]
}
```

**为什么要单独一层**：面经条目的 `summary` 是论坛原帖（吐槽 + 流水账 + 内推码），
而面经又是**时效性最强**的内容 —— 想回答"字节二面考了什么"不该让你逐条点开。
这一层把公司/轮次/结果/主题抽成结构化字段，直接支撑「面经速览」面板。

**为什么用规则而不是模型**：规则会漏，但**不会编**。面经标题写法高度固定，
规则足够准且每一条都能对着原帖核对；模型抽取放在深读层做补充。

两个实测踩过的抽取坑（都写在代码注释里）：
1. **结果判定必须先测负面**。`凉经`（失败）曾被判成"通过"，因为宽松的 `offer`/"过"
   先命中了；现在顺序是 未通过 → 待定 → 通过。
2. **不能只靠标题里有"面试"**。宽松匹配会把"千万不要对面试官抱有太多滤镜！"
   "offer选择求助"这类**没有面试内容**的帖子算进来；现在要求标题含
   面经/挂经/凉经/笔经，或含明确的轮次词（一面/二面/三面/HR面）。

## 17. 契约违反的后果（迁移时最容易忽略）

| 违反 | 后果 |
|---|---|
| 改了 id 算法 | 收藏、进度、解析全部失联；去重失效 |
| `category` 用了 taxonomy 里没有的值 | selfcheck 警告；UI 走兜底映射 |
| `digest.items` 不是 index 的子集 | selfcheck 报「orphans」 |
| 时间戳不带偏移 | 排序/新鲜度计算错乱 |
| 写 JSON 用了 BOM | JSON 解析失败，页面空白 |
| 整体覆盖 `enrichment.json` 而非合并 | **丢失历史解析**（不可逆） |
| 把 `state/` 或 `inbox/` 发布到公网 | 泄露内部状态与个人备注 |
| `formulas[].latex` 用了自研渲染器不支持的命令 | **公式页整页空白**（有门禁拦） |
