# 00 · 迁移总览（把这个工作台搬到别的模型 / Agent 平台）

> 这份文档的目标：**让另一个 AI、另一台机器、另一个 Agent 平台能够完整重建并维护这套工作台**，
> 而不需要读原始对话。所有接口、字段、路径、命令都来自**当前代码的实测**，不是设计意图。

---

## 1. 这套东西是什么

一个**每日 18:00 (Asia/Shanghai)自动联网调研 + 深度解析的求职学习工作台**。

拆成两个可独立替换的层，这是整个架构最重要的一个决定：

```
┌─ 第 1 层：确定性采集层（无 LLM、无第三方依赖） ────────────────────────┐
│  scripts/collect.py        30 个渠道 -> 规范化 -> 分类 -> 打分           │
│                            -> 4 层去重 -> 原子落盘                       │
│  scripts/selfcheck.py      数据完整性 + 采集质量断言                     │
│  scripts/plan_deep_read.py 质量闸门 + 每类配额 -> 深读清单               │
│  产物：web/data/*.json                                                   │
└──────────────────────────────────────────────────────────────────────────┘
                                  ↓ 读写同一批 JSON
┌─ 第 2 层：Agent 深读层（需要一个 LLM） ─────────────────────────────────┐
│  提示词：scripts/daily-agent.md                                          │
│  任务：读深读清单 -> 产出讲解/图解/公式/提案 -> 合并写回                 │
│  产物：enrichment.json / formulas.json / jobs.json / proposals/*.json    │
└──────────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─ 第 3 层：纯静态前端（零依赖、无构建期框架） ───────────────────────────┐
│  web/index.html + web/assets/{css,js}                                    │
│  单一数据适配器读取 web/data/*.json，界面与数据层完全解耦                │
└──────────────────────────────────────────────────────────────────────────┘
```

**为什么一定要这样分层**：LLM 不可用、额度用尽、提示词改坏 —— 这些都**不能让采集停摆**。
第 2 层失败时，第 1 层照常出数据，前端照常渲染，只是卡片上会明确显示「仅摘要」。

## 2. 迁移到别的平台：三档选择

### 档位 A · 只搬前端（最省事，5 分钟）
工作台是**纯静态**的。把 `web/` 整个目录拷到任何静态托管就完事。
数据是 `web/data/*.json`，没有任何后端。
→ 适合：你只想换个地方看，不想维护采集。

### 档位 B · 搬"采集 + 前端"，用别的 Agent 做深读（推荐）
1. 拷 `web/`、`scripts/`（Python，**仅标准库**）、`config/`、`research/source_registry.json`
2. 把 `scripts/daily-agent.md` 交给你的平台（Claude Code / Cursor / Codex / 自建 agent 都行）
3. 让它按提示词读写 `web/data/`，**唯一硬性接口是那几个 JSON 的字段结构**

这是**最关键的迁移点**：第 2 层与平台**解耦**。
提示词里没有任何对某个模型或某个工具的名字依赖，只要求「能读写文件、能跑 Python」。
→ 适合：换模型、换平台，但保留整套数据契约与自检体系。

### 档位 C · 全套搬到另一台机器
1. 拷整个仓库
2. 装 Python 3.8+（**不需要 pip install 任何东西**）与 Node 18+（只为前端构建与校验）
3. 跑 `python scripts/build_seed_placeholders.py` 生成占位数据（让前端先能渲染）
4. 跑一次 `scripts/collect.py` 拉真实数据
5. 按 [03-自检与自我迭代](03-自检与自我迭代.md) 接好定时任务
6. 用 `python scripts/audit_requirements.py` 与 `node scripts/verify-web.mjs` 验收

## 3. 迁移前必须理解的数据契约（先读这份）

| 要点 | 为什么迁移时最容易踩 |
|---|---|
| `web/data/items/index.json` 是**唯一真相** | 其他文件都是从它派生或与它关联的视图 |
| 稳定 id = `sha1(sourceId + externalId)[:16]` | **换平台不要改算法**，否则去重全失效、历史状态（收藏/进度）全部丢失 |
| 时间戳一律带偏移的 ISO-8601（`+08:00`） | 内部计算用 UTC，展示用 Asia/Shanghai；**禁止裸时间** |
| `state/collector-state.json` 是**私有状态**（去重指纹、blocklist） | 不要发布到公网；删掉它 = 去重记忆清零 |
| `enrichment.json` 按 item id 键控，**与语料解耦** | 重建语料不会丢解析；Agent 失败也不会污染语料 |
| 分类 id 稳定，只能新增不能改名 | 改名会让历史卡片的分类失效 |

完整字段表见 [02-数据契约](02-数据契约.md)。

## 4. 每日流程与自主性（迁移时要一起搬走的"行为"）

```
18:00 触发
  → collect.py        采集/分类/打分/去重（确定性，无 LLM）
  → selfcheck.py      数据完整性 + 采集质量断言（影响退出码）
  → plan_deep_read.py 质量闸门 + 每类配额 -> queue（新条目）+ backfill（旧解析不完整）
  → daily-agent.md    深读：讲解/图解/公式/提案（需要 LLM）
  → tune_keywords.py  关键词自动调优（reviewPolicy 里唯一允许自动生效的一类）
  → run_guards.py     公式渲染门禁（失败则拒绝发布）+ 布局体检
  → build_site.py     生成 dist/
  → publish-workbuddy 审计 dist/ 并交接给 WorkBuddy 发布（失败不影响本地数据）
```

细节见 [01-每日更新流程](01-每日更新流程.md) 与 [03-自检与自我迭代](03-自检与自我迭代.md)。

## 6. 迁移验收清单（照抄即可）

```bash
# 1. 环境（两者都不需要 pip install / npm install）
python -c "import sys; print(sys.version)"     # >= 3.8
node -v                                        # >= 18（仅前端构建与校验用）

# 2. 数据层自洽
python scripts/selfcheck.py
python scripts/audit_requirements.py           # 期望 55/55
python scripts/audit_autonomy.py               # 期望 0 缺失

# 3. 前端
node scripts/check-parts.mjs
node scripts/build.mjs
node --check web/assets/js/app.js
node scripts/check-formulas.mjs                # 公式渲染门禁
node scripts/verify-web.mjs                    # 期望 13/13 路由

# 4. 端到端
python scripts/collect.py --only arxiv,hf_papers --limit 5 -v   # 小样本试跑
python scripts/build_site.py                                     # 产物 + 隐私审计
```

**四个"必须有"**：`selfcheck` 0 错误、`audit_requirements` 55/55、`audit_autonomy` 0 缺失、
`verify-web` 13/13。任何一个不达标都说明迁移没完成。

## 7. 最小可行迁移（如果时间很紧）

只搬这三样，工作台就能跑起来并且**不会骗人**：

1. `web/`（前端 + 数据）
2. `scripts/collect.py` + `config/collector.config.json`（采集）
3. `scripts/selfcheck.py`（自检 —— **不要省这一个**，没有它你不知道数据是不是坏的是否还准）

深读层、守卫、发布都可以后补。**自检不能省**：它是"数据可信"的唯一证据。
